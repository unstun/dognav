## 10 秒视觉预览不能套用完整时长行人比例门

- 日期：2026-08-19
- 任务：`office_crowd_mid360_dualview_preflight01/02`。
- 现象：`preflight01` 的 10 秒实体录制已经完成，但误用了完整运行的行人 50%/95% motion fraction 门，导致合成前失败；该运行按 immutable failure 保留，没有覆盖或改写为 PASS。
- 已验证原因：完整时长比例阈值按整条路线和完整时域定义，短预览只覆盖启动后的局部窗口，两者不是同一统计总体，不能共用晋级判定。
- 预防：显式区分 `short visual preflight` 与 `formal full-duration gate`。短预览只检查短窗 motion coherence，并将 terminal goal/stop 记为 `SKIPPED`、full-duration pedestrian fractions 记为 `NOT_GATED`；完整门只能在获批的完整运行中执行。
- 证据：`.pipeline/experiments/2026-08-17_office_l0_scan_crowd/REPORT.md`、`.pipeline/experiments/2026-08-17_office_l0_scan_crowd/revision_ledger.json`、`.pipeline/experiments/2026-08-17_office_l0_scan_crowd/results/office_crowd_mid360_dualview_preflight02/office_pedestrian_motion_audit.json`。
- 后续意义：门禁必须与运行时长和 claim 对齐；把完整门机械套到短 smoke/preflight 会制造假失败，把门跳过却不显式标注则会制造假通过。

## 原生 RViz 必须是 5070 Ti 同 run 数据并按仿真时间对齐

- 日期：2026-08-19
- 任务：Office 黄金双视角中的 native RViz 证据恢复。
- 现象：本地渲染的 3D panel、post-run overlay 或独立 replay 都不能证明 5070 Ti 上 SCAN、Lite3 measured state 与相机画面来自同一次执行；直接按墙钟拼接还会在低实时率运行中产生错帧。
- 已验证原因：原生 RViz 的证据价值来自 live same-run Foxy topics；Isaac 仿真时间与捕获墙钟不是同一时域，必须记录同 run 观察关系，再把每个 camera trace simulator-time frame 映射到实际捕获的 RViz source frame。
- 预防：在 5070 Ti 同一 run 内录制原生 Foxy RViz，保留 live audit 和 source capture；用单调时钟建立观察关系，再按 simulator-time camera trace 一对一选择 RViz 帧，不合成或 replay SCAN 数据。最终 artifact 必须核对帧数、解码和远近端 SHA-256。
- 证据：`.trellis/tasks/08-17-office-crowd-review-visual-r2/codex-native-rviz-review.md`、`integration/lite3_sim_bridge/lite3_sim_bridge/rviz_time_sync.py`、`.pipeline/experiments/2026-08-17_office_l0_scan_crowd/results/office_crowd_mid360_dualview_preflight02/native_rviz_review_audit.json`。
- 验证：`preflight02` 的 native RViz live audit PASS；最终 RViz entity 与 camera trace 同为 251 帧，双视角合成为 25 fps、10.04 s。
- 后续意义：native RViz 的 UI 外观相似不足以证明来源；没有 same-run topic、仿真时间映射和 live audit 的视频只能是诊断展示，不能作为交付或验收证据。
