# 长期工作流

- 更新日期：2026-08-19

## 实验变更必须版本化

- 每次改动或远程执行前，先明确当前阶段、新 revision、唯一 change group、冻结项、预期证据/门禁和未授权动作；一个 revision 只对应一个清晰变更组。
- revision 是源码/配置状态，run ID 是该 revision 的一次不可变执行；candidate 只能在所声明自动门通过后提升。失败或被取代的 run 不覆盖、不重命名。
- automated gate、Dr Sun 的 human gate 和 presentation contract 独立记录；冻结视频模板不等于接受导航候选，short preflight 不得写成 formal candidate 或完整验收。
- 执行后将运行结果、证据路径/哈希、自动状态、人工状态和下一个已授权动作写入 revision ledger，使“当前在做什么”可直接审计。
- Office L0 的实施细则以 `.pipeline/experiments/2026-08-17_office_l0_scan_crowd/CHANGE_CONTROL.md` 和 `revision_ledger.json` 为准。

## 归档必须回到主项目可见状态

- 隐藏 worktree、临时分支或远端执行副本中的最新内容不能单独算作归档完成；源码、任务索引、热区和证据路径必须能从主项目的 canonical branch 直接发现。
- 运行实体从其他 worktree 或远端回收时，复制到主项目相同相对路径，保留源副本，并对源/目标做递归 SHA-256 比对；视频等大二进制按仓库政策留在本机，Git 中保留路径、哈希和文本证据。
- 回答“现在做到哪里”前，若热区、Trellis、`.pipeline` 或 Git 状态不一致，先枚举全部 worktree/branch 并核对实体证据；不能只读默认 checkout 后凭旧摘要回答。
- 归档收口必须在主项目重新执行台账验证和相关质量门；验证失败或实体缺失时，不得声称状态已同步。
