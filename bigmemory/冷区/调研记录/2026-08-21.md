### 已复核证据

- 新 profile 中，同一扫描的 raw cloud 发往 `/quad_0/cloud_raw` 供 RViz 展示，planner cloud 发往 `/quad_0/cloud` 供 SCAN；101 个扫描 ID 均成对，且 raw、planner 与 ground 点数守恒关系成立。
- 10.04 s 传输版视频为 9,515,787 bytes，H.264 High / yuv420p、3840x1080、25 fps、251 帧；全解码通过，SHA-256 为 `2b6009e80ba12c109fd6aee7fadfa2eb190e4d8e0369ac495d02152c246400be`，1/5/9 s 抽帧中点云可见。
- 仿真时间频率为 10.0000002 Hz，墙钟只有约 0.539 Hz。RViz `Decay Time = 0` 保留最新帧，因此视觉上可持续显示，但这不能表述为墙钟 10 Hz 刷新。
- 重跑结果为 targeted 86 tests PASS，本地全量 153 tests PASS / 2 skips；归档的 Foxy targeted 25 tests 和 4 个 CTests PASS。Foxy bridge 整包因环境缺少 `torch` 未完整通过。
- 再次对照 SCAN-Planner commit `348e8a590a50a5a6bbab8d8c6dcfd171f009be26` 的官方 [`advanced_param.xml`](https://github.com/wuyi2121/SCAN-Planner/blob/348e8a590a50a5a6bbab8d8c6dcfd171f009be26/src/planner/plan_manage/launch/advanced_param.xml)，确认本地仅选择性借用 Go2 几何值；上游 `max_vel=0.75 m/s` 与 `horizon=3.5 m` 没有借用，本地仍保持 Lite3 `0.50 m/s` 和 Office `8 m` 视野。

### 新发现的验收缺口

- 默认 legacy V1 只发布 `/quad_0/cloud`，而共享 RViz/voxel 配置已改为监听 `/quad_0/cloud_raw`；因此新 profile 正常不等于旧模式无回归。
- 远端 manifest 声明 130 个文件，本地对比只有 66 个匹配、63 个缺失，并有 1 个 `closed_loop.mp4` 不一致；所以本地还不具备完整实体回收证明。
- 顶层 `AGENTS.md` 和 parent task meta 仍保留旧 revision 状态，与热区及 manifest 的当前记录不一致。
- 配置声明的 1 s connect timeout 未传入 telemetry client，实际客户端仍使用 10 s receive timeout；该参数尚未形成可执行合约。

### 结论

平地新 profile 的双点云核心证据可以记为“有条件通过”，但上述回归、实体回收和状态一致性缺口阻止整体版本验收。`accepted_revision` 和 `formal_candidate` 应继续为空，任务保持 `in_progress`。
