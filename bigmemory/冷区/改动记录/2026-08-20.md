## v2.0.1 双点云分流与 SCAN 原版 Go2 几何参数接入

- 日期：2026-08-20
- 任务：`08-20-v2-0-1-cloud-traversability`；构建 revision 为 `office-v2.0.1-go2-geometry-preflight`，profile 为 `upstream_go2_reference`。
- 行为改动：在保留 `SENSOR_FRAME_V1` 兼容的同时，新增原子双点云帧 `SENSOR_FRAME_DUAL_CLOUD_V1`。同一 MID-360 scan 生成保留有限且量程内全部点的 `/quad_0/cloud_raw` 和经局部最低面几何过滤的 `/quad_0/cloud`；双方共用 scan ID、时间戳和坐标系，并记录 raw/ground/planner/conservative-retention 点数。Foxy 从一个解码帧连续发布两份 `PointCloud2`，新 profile 缺任一点云即失败，旧 profile 仍可使用 V1。
- 过滤与展示边界：过滤器不读取 Isaac 场景/地形标签；连续局部最低面作为地形候选，高出包络的点作为障碍，支撑不足点保守留在规划云中。原生 RViz `Live LiDAR Cloud` 改为持续显示 `/quad_0/cloud_raw` 且 Decay 保持 0；SCAN 仍只订阅 `/quad_0/cloud`。
- Go2 借用参数：独立 profile 只引入官方 SCAN-Planner 的 `double_cylinder_radius=0.25`、`double_cylinder_offset=0.18`、`body_height=0.40`、`obstacles_inflation_z_up=0.10`、`obstacles_inflation_z_down=0.10`。Lite3 最大速度仍为 `0.50 m/s`，Office 地图/视野、MID-360、V12 策略、控制器和场景门限未随 Go2 漂移；这些值不被表述为 Lite3 标定参数。
- 三维路线：SCAN reference-path 模式把 `Path` 的 Z 作为局部地面高度，再加 `body_height=0.40 m`；新增规划机身高度、真实机身高度与局部地面高度残差审计。原有 z 方向梯度抑制和只发送前进/横移/转向的控制边界保持不变。
- 验证：本地全量 Python 测试 `153 tests` 通过、`2` 项按环境跳过；针对性 Foxy bridge 测试 `25` 项通过；SCAN 四个 CTest target 通过，其中包括 reference-path height GTest。`office_v2_0_1_go2_geometry_preflight02` 完成 10.04 秒平地 Office 短回归：101 帧 sensor 审计对应 101 帧 Foxy 审计，scan ID 为 1--101，无重连和 I/O error；原生 RViz 点云连续性在恢复后处理中为 101/101 且视频 251/251 帧可见。
