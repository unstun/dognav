# 记忆文件格式规范

## 热区容量预算

| 文件 | 上限 | 内容约束 |
|------|------|----------|
| 状态简报.md | 1500字 / 30行 | 活跃任务≤3条,关键上下文≤5条 |
| 未关闭决策.md | 1200字 / 25行 | 未关闭≤15条,已关闭保留7天后删除 |
| 近期改动.md | 1000字 / 25行 | 7天滚动窗口 |

热区总预算约 3700 字。每次更新后须在预算内。
热区是**全量重写**,不是追加。

## 热区文件格式

### 状态简报.md

```markdown
# 项目状态简报
> 最后更新：YYYY-MM-DD HH:MM

## 当前在做什么
- [任务描述]（≤3条）

## 关键上下文
- [影响当前工作的重要背景]（≤5条）

## 近期警告
- ⚠ [需要注意的事项]
```

### 未关闭决策.md

```markdown
# 未关闭决策

- [ ] [决策描述]（提出日期：YYYY-MM-DD）
- [x] ~~[已关闭决策]~~ → [结论]，YYYY-MM-DD
```

### 近期改动.md

```markdown
# 近期改动摘要
> 滚动窗口：最近 7 天

## YYYY-MM-DD
- [改动摘要]
```

滚动规则:
- 今天/昨天:每天≤3条
- 2-4天前:每天≤2条
- 5-7天前:每天≤1条
- 超过7天:删除

## 冷区按天文件格式

文件命名:`YYYY-MM-DD.md`,同一天多次写入使用追加模式。
每条记录用二级标题分隔:`## HH:MM — 简述`

### 改动记录/YYYY-MM-DD.md

```markdown
## HH:MM — [改动简述]
- **原因**：[为什么要改]
- **改动**：[文件路径 + 改了什么]
- **状态**：[进行中/已完成/已回滚]
```

### 踩坑记录/YYYY-MM-DD.md

```markdown
## [坑的简述]
- **现象**：[看到了什么]
- **原因**：[根因分析]
- **解决**：[解决方案/命令]
- **预防**：[如何避免再次踩坑]
```

### 调研记录/YYYY-MM-DD.md

```markdown
## HH:MM — [调研主题]
- **背景**：[为什么要调研]
- **来源**：[URL / 论文 / 文档]
- **关键发现**：[发现列表]
- **结论**：[调研结论]
```

### 心路历程/YYYY-MM-DD.md

```markdown
## [主题]
[思路变化、决策原因、反思、对项目方向的想法]
```

### 里程碑/YYYY-MM-DD.md

```markdown
## [里程碑名称]
- **达成内容**：[具体完成了什么]
- **关键指标**：[数据/效果]
- **下一步**：[后续方向]
```

### 会话记录

完整聊天记录不再写入 bigmemory。需要留存的信息应拆成改动记录、踩坑记录、调研记录、心路历程或里程碑，避免长期保存原始对话。

## 置信度 Frontmatter 规范

### 适用范围（试点）

| 目录 | 加 frontmatter | 说明 |
|------|----------------|------|
| `.pipeline/survey/*.md` | 是 | 调研结论，置信度最关键 |
| `bigmemory/冷区/调研记录/*.md` | 是 | 调研原始记录 |
| `.pipeline/contracts/*.md` | 是 | Research Contract，需区分草稿与已审阅版本 |
| `.pipeline/experiments/*.md` | 是 | 实验台账，后续分析会反复引用 |

暂不覆盖：热区（容量预算紧张）、冷区其余子目录、`.pipeline/literature/`、`.pipeline/terminology/`。

### Frontmatter 格式

````markdown
---
origin: ai+web
reviewed: false
---
````

### origin 判定标准

| 值 | 语义 | 判定标准 |
|----|------|----------|
| `ai_only` | 纯 AI 生成，无外部证据 | 文内无可追溯来源 |
| `ai+web` | AI 生成 + 联网检索佐证 | 文内有 URL / DOI / 文献 CitationKey |
| `human` | Dr Sun 原创 | Dr Sun 手动标注 |

### reviewed 规则

- `/archive` 写入时默认 `reviewed: false`
- Dr Sun 审阅后手动改为 `reviewed: true`
- AI（任何 agent）编辑 `reviewed: true` 的文档 → 一律重置为 `reviewed: false`

### 信任矩阵

| origin | reviewed | 有效信任度 | AI 引用行为 |
|--------|----------|-----------|------------|
| `ai_only` | `false` | 最低 | 标注"（AI 生成，未验证）"，不可作为决策依据 |
| `ai_only` | `true` | 中 | 可引用，标注出处 |
| `ai+web` | `false` | 低 | 标注"（联网调研，待确认）"，可用于初步分析 |
| `ai+web` | `true` | 高 | 可直接引用，视为可靠 |
| `human` | `true` | 最高 | 可直接引用，视为可靠 |
| `human` | `false` | 中 | 可引用，标注"（人工原创，AI 修改后待复审）" |

### 无 frontmatter 文档

试点范围内无 frontmatter → 视为 `origin: ai_only, reviewed: false`（最低信任），
引用时标注"（无元数据，待迁移）"。试点范围外不受约束。

### 冷区日文件特殊处理

`bigmemory/冷区/调研记录/YYYY-MM-DD.md` 采用追加模式：
- 文档级 origin 为聚合值，取所有条目中最低来源
- 追加或编辑时重置 `reviewed: false`
