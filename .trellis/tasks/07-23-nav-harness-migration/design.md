# Design: Navigation Project Harness Migration

## Boundary

The migration copies reusable behavior and tooling, not the locomotion
project's accumulated state. The target repository owns all resulting files.
The source repository is read-only reference material.

## Components

### Repository instructions

Keep the target's existing issue-tracker guidance and add the common research
discipline from `machine-dog`. Navigation-specific rules replace locomotion
training labels, paths, and remote-run assumptions.

### Trellis

Initialize Trellis 0.6.7 from the installed CLI with Codex, Claude Code, and
Cursor adapters. Keep generated framework files. Configure
`session_auto_commit: false`. Do not copy source tasks, workspace journals,
runtime pointers, backups, or backend specs.

### Agent platforms

Use Trellis-generated platform adapters as the baseline. Add only the
project-level git-state, memory-freshness, and reviewed-state hooks that remain
valid for the navigation repository. Keep hooks path-relative to the repository.

### Skills

Keep existing third-party skill symlinks. Copy a curated set of non-conflicting
skills into `.agents/skills/` as the tracked canonical copy, then link them into
`.claude/skills/`. Adapt project-specific wording and paths before validation.

### Pipeline and memory

Create empty navigation-specific indexes and templates. The initial state must
say that literature exists but code, simulation, checkpoints, and runtime proof
do not. No source experiment ledger or old memory entry is copied.

## Compatibility

- Existing Matt Pocock skills continue to be regenerated by
  `sync-skills.sh`.
- Trellis-managed files remain updateable with `trellis update`.
- Project-owned hook and skill additions remain outside Trellis-managed blocks.

## Rollback

The migration is isolated to new harness paths plus deliberate edits to
`AGENTS.md` and `.gitignore`. Before commit, the full change can be removed
without touching `docs/research/` or navigation code.
