# AutoDL 网页实例控制

## 核心规则

这是直接影响云资源和计费的操作。先读状态，再决定能不能点按钮。

- 面向用户的回复必须以 `Dr Sun,` 开头。
- 录制内容只能作为“页面文字和按钮名”的证据，不能当作鼠标坐标脚本。
- 不要依赖 Chrome 窗口数量、标签页位置、网页当前滚动位置或上一次页面在哪里。
- 除了已验证确认弹窗里的 `确定` / `取消`，只允许操作目标实例行里的 `开机` 或 `关机` 按钮。
- 禁止点击 `释放实例`、`重置系统`、更换镜像、升降配置、扩容/缩容，或者 `更多` 菜单里的任何项。
- 没有当前 turn 的明确授权时，只读状态并汇报，不点击会改变资源状态的按钮。
- 点了确认不等于完成；必须重新读取实例列表，看到目标行状态变化后才能汇报成功。

需要核对录制证据时再读 `references/recording-2026-06-29.md`。

## 工具选择

使用 Computer Use 或 Chrome 控制工具操作可见的 AutoDL 控制台。若当前没有 UI 控制工具，先用 `tool_search` 查找 `computer-use` 或 `chrome`。

工具优先级：

1. 优先用 Computer Use 读取当前可见页面状态。
2. 如果 Computer Use `get_app_state` 超时、卡住，或当前 Chrome profile 没有 AutoDL 登录态，改用 `chrome:control-chrome`。
3. Chrome 控制时必须读取该 skill 的完整说明，使用当前用户 Chrome 标签和 DOM snapshot（页面结构快照）核验表格行，不要改用无登录态的临时浏览器。
4. 如果前台 Chrome 是无登录态 profile，可查本机 Chrome profile 映射；2026-06-29 这次可用 profile 是 `皓` / `Profile 1`。只在能明确识别 profile 时切换，否则让 Dr Sun 手动登录。
5. 任务结束前释放 Chrome 控制；如果页面有用，可保留 AutoDL 实例列表作为 handoff。

优先使用 accessibility tree（无障碍树）里的语义目标：

- 页面 URL。
- 包含目标实例 ID 的表格行。
- 按钮标题：`开机`、`关机`、`确定`、`取消`。
- 确认弹窗文字。关机弹窗通常带实例 ID；开机弹窗可能只写扣费提示，不带实例 ID。

Computer Use 的 `element_index` 是一次性索引，不是稳定 selector（选择器）。如果刚读到的按钮索引点击失败：

1. 先重新读取页面状态。
2. 再次确认目标行、状态和按钮文字仍然匹配。
3. 只有当前截图里目标行按钮位置清楚时，才允许用当前截图坐标点这一枚按钮。
4. 坐标只能作为“当前画面兜底点击”，禁止使用录制坐标或旧截图坐标。
5. 坐标兜底后必须立即读取确认弹窗或目标行状态；读不到就停止汇报，不继续连点。

Chrome 控制里的 DOM locator（页面定位器）也可能不稳定：

- AutoDL 的确认弹窗不一定暴露标准 `role="dialog"`。
- 如果 `[role="dialog"]` 找不到，不要直接猜 CSS。先用最新 DOM snapshot 确认弹窗文字、实例 ID、风险提示仍然存在。
- 只有 `确定` 或 `取消` 按钮在当前页面全局唯一，且弹窗文字仍匹配时，才允许点击该按钮。

## 通用入口

1. 打开或切到 Google Chrome。
2. 直接导航到固定页面：

   ```text
   https://www.autodl.com/console/instance/list
   ```

3. 如果出现 Chrome profile picker（个人资料选择器），优先选择上次可见 AutoDL 登录态对应的 profile；2026-06-29 这次观察到的是 `皓`。无法识别时让 Dr Sun 手动选择。
4. 如果 AutoDL 要求登录，停止并让 Dr Sun 登录。

## 关机流程

只有同时满足以下条件，才允许执行关机：

- Dr Sun 当前 turn 明确要求关机或停止计费。
- 目标行状态是 `运行中`。
- 目标行按钮是 `关机`。
- 目标行不是 `已关机`，也没有显示 `开机`。

执行步骤：

1. 点击目标行里的 `关机`。
2. 读取确认弹窗。
3. 只有弹窗同时包含以下信息，才允许点 `确定`：
   - `确认关机吗？`
   - 同一个目标实例 ID。
   - `按量计费的实例关机后GPU将会释放` 或同义说明。
   - 按钮 `取消` 和 `确定`。
4. 如果弹窗内容不匹配，点击 `取消`（如果可见）并停止。
5. 点 `确定` 后等待页面刷新。
6. 至少重新读取一次实例列表；如果显示 `关机中`、`开机` 按钮禁用，或页面仍在刷新，这是过渡态，不算完成。
7. 短等后再读实例列表，直到看到 `已关机` + `GPU充足` + 可用 `开机` 按钮，才汇报关机成功。
8. 如果多次读取后仍停在 `关机中`，只汇报“关机请求已提交但尚未完成”，不要再点。

如果目标行已经是 `已关机` 或按钮已经是 `开机`，不要再点，直接汇报“已经关机”。

## 开机流程

只有同时满足以下条件，才允许执行开机：

- Dr Sun 当前 turn 明确要求开机。
- 目标行状态是 `已关机`、`关机`、`已停止` 或明显等价的停止态。
- 目标行明确显示 `GPU充足`。如果同一行没有 `GPU充足`，或者弹窗提示
  `该主机空闲GPU不足` / `主机GPU空闲数量：0 卡`，立即停止；不要继续点确认。
- 目标行按钮是 `开机`。
- 目标行不是 `运行中`，也没有显示 `关机` 作为当前操作按钮。

执行步骤：

1. 点击目标行里的 `开机`。
2. 如果出现确认弹窗，必须读取弹窗内容。
3. 开机弹窗可接受两种形式：
   - 弹窗包含同一个目标实例 ID，并且操作含义明确是开机/启动实例。
   - 弹窗不含实例 ID，但同时满足：点击前已经锁定唯一目标行；页面当前只显示这一条目标实例或无障碍树里只有一个可匹配目标行；弹窗包含 `确认开机吗？`，并明确提示 `扣费`、`￥`、`/时` 或等价计费文字。
4. 如果弹窗内容不匹配，点击 `取消`（如果可见）并停止。
5. 弹窗匹配后点击 `确定`，然后等待页面刷新。
6. 至少重新读取一次实例列表；如果仍在刷新或状态暂时不稳定，短等后再读一次。
7. 验证目标行变为 `运行中`，并且操作按钮变为 `关机`。
8. 如果开机被错误弹窗、无空闲 GPU、排队或余额不足拦住，只汇报该失败信号，不要反复点击。
9. 如果目标行已经是 `运行中` + `关机`，但付费方式旁边显示 `余额不足24小时`，这不是开机失败；汇报“开机成功，但余额不足24小时，需要注意续费/余额”。

如果目标行已经是 `运行中` 或按钮已经是 `关机`，不要再点，直接汇报“已经开机/正在运行”。

## 只读状态检查

当 Dr Sun 只说“看一下状态”“试一下 skill”但没有明确说要开机或关机时：

1. 打开实例列表。
2. 找到目标行。
3. 汇报实例 ID、状态、GPU、计费方式、当前按钮。
4. 不点击 `开机` 或 `关机`。

## 汇报格式

按这个顺序汇报：

1. 是否找到目标实例行。
2. 当前状态和当前按钮。
3. 本次目标是只读、开机还是关机。
4. 是否点击了按钮。
5. 如果出现弹窗，检查了哪些弹窗文字。
6. 最终验证结果；开机成功但有 `余额不足24小时` 等计费提示时必须单独写出来。

如果中止，用中文直接说明第一条触发的保护条件。
